# 存档数据勘察与决策上下文审计

> 方法：用 SaveDump 反序列化真实存档全部分模块（_1.._11/_2X），核对反编译运行时 API，
> 判定哪些字段已接入 Agent 决策上下文、哪些未接入。目标：决策数据完备且简洁。

## 一、存档模块结构（SaveManager 写入）

| 模块 | 内容 |
|---|---|
| `_1` | 全局 GameData（日历/胜利条件/难度/迷雾/起始人口经济） |
| `_2X/_2` | Save_GameData2（省份/军队大对象 1MB） |
| `_3` | `lCivsDiploData`：外交条约档案（防御条约/保障/军事通行/互不侵犯/停战） |
| `_4` | `lProvincesData`：每省全量（发展/满意度/革命风险/8建筑/核心/真主人/经济/军队/领域变化） |
| `_5` | `lPlayers`（玩家 civID + 已发现列表） |
| `_6` | 同盟列表 |
| `_7` | 战争列表 `lWars` |
| `_8` | 和平条约 |
| `_9` | 瘟疫 |
| `_10/_11` | 神圣罗马帝国 / 事件 |

## 二、已接入 Agent 决策上下文（✅）

| 数据 | 来源 | 进 LLM 的形式 |
|---|---|---|
| 回合/日期 | `_1` iTurnID/iDay/iMonth/iYear | `T16 日期1442年7月` |
| 我方国力 | Civ 运行时 API | 金币/省份/军队/行动点/科技等级/首都/科技点 |
| 8 类技能投放 | skills | 已投点数各级 |
| 省份明细 | `_4` 提炼 | 每省 人口/开发/经济/驻军/堡垒/首都 |
| 稳定度聚合 | `_4` fHappiness/fRevolutionaryRisk/iTrueOwner | 均满意度/最高革命风险/核心省x/非核心y |
| 邻国国力画像 | 引擎 Civ API | 省/军/人口/金/科技/关系/同盟/交战/首都/接壤 |
| 外交条约 | `_3` + 引擎 getter（停战/互不侵犯/防御条约/保障） | `条约: civ48(停战2) civ55(互不侵犯4)` |
| 战争列表 | `_7` 实时 | `战争: w57→48` |
| 科技点/消息 | skills/messageBox | 剩余点/消息类型（区分突发） |

## 三、未接入（❌ 与原因/优先级）

| 数据 | 决策价值 | 未接入原因 | 优先级 |
|---|---|---|---|
| 胜利条件（VICTORY_CONTROL_*等） | 高（终局目标） | 引擎 getter 未定位 | P1 下批 |
| 外交点（DiplomacyPoints） | 中（条约资源上限） | getter 简单可加 | P1 |
| 意识形态/政体（Ideology） | 中（战略风格） | 字段多需精选 | P2 |
| 8 类建筑全明细（库/坊/港/补给/望塔/农场） | 中（建造决策） | 已取 fort；补齐后省份明细变长 | P2 |
| 附庸/傀儡关系 | 中（保护关系） | 引擎字段直达 | P2 |
| 瘟疫/革命事件 | 低-中（偶发） | 低频 | P3 |
| HRE/神圣罗马 | 低 | 本剧本无 | 跳过 |
| 已发现世界（met province） | 低 | 已开迷雾 | 跳过 |
| 经济明细（taxation/production 拆分） | 低 | 聚合已达 | 跳过 |

## 四、原则

- **简洁有效不啰嗦**：LLM 上下文每回合 < 400 token；聚合作法（稳定度/条约）替代逐条列表
- **实时优先**：所有数据以引擎内存实时 API 为准（会话内存），存档为辅（离线回放）
- 计划模式（10 回合 1 次调用）下上下文成本 amortize 收敛
